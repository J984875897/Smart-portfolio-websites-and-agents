# S05 候选筛选：设计评审稿

日期：2026-10-17。状态：设计按用户要求调整先后顺序，S05-A／B／C开发验收通过（见 [A验收](../../../outputs/acceptance/S05A/README.md)、[B验收](../../../outputs/acceptance/S05B/README.md)、[C验收](../../../outputs/acceptance/S05C/README.md)）。真实完整候选规模及历史候选认证仍未通过；页面只检查范围和数量，尚不生成组合。

依据：[总流程 S05](../plans/2026-10-12-portfolio-development-workflow.md)、[研究政策](../../../configs/research_policy.yaml)、[S04 实测](../../../outputs/acceptance/S04/README.md)。

## 1. 本步回答的问题

用户指定市场、工具类型、经济类别、个股模式和目标持仓 K 后，系统解释：哪些产品在范围内，哪些数据合格，合格数量 N 是多少，数量比例是否允许继续研究。

这一步不选出 K 个成员，不分配权重；数量条件通过不等于组合已生成，也不说明分散化或风险已经合格。相关性／分散化在 S06／S07，utility 在 S08，做空在 S09。

## 2. 方案选择

| 方案 | 好处 | 代价与限制 |
| --- | --- | --- |
| 先接现有月度数据，再验证筛选与数量规则，最后做界面（用户指定） | 先看清实际输入、数据缺口及资格证据，规则建立在可核对的数据接口上 | 数据接入阶段不计算正式候选数 N，分类过滤和比例检查在下一单元交付 |
| B：先补齐真实来源和历史名单认证再开发 S05 | 从真实全链路开始 | 依赖尚未获得的数据，无法先验证已明确的业务规则 |
| C：直接用已导入产品总数做 N | 很快出现界面 | 会把缺月、重复和未换成 HKD 的产品计入，违反已确认需求，不采用 |

采用用户指定的先数据、后规则顺序。真实路径第一版定位为“当前资产池的回溯研究”，保留声明时间证据标签；不声称历史候选池完整。历史时点认证模式保持不可用，不提供可任意勾选的“历史已认证”按钮。

## 3. 输入与计数

### 3.1 数据资格

基线是同一结束月、同一决策时点、固定连续 60 月的 HKD 月度收益。沿用 S03-B 的逐月收益、FX 和声明时间逻辑；缺月、重复冲突、无效数值、缺时间证据均排除。不补零、不用窗口外历史补缺。

输入保留原币与来源字段，只有 HKD 分析矩阵进入后续估计。导入行数、下载成功数、C3 通过月数均不能直接成为 N。C2/C3 尚未接入共同窗口，本阶段不增加该桥接，也不解除 partial 来源阻止。

用户可调整结束月份和含时区的决策时间；S05 第一版窗口固定 60 月，避免不同产品用不同长度凑数。结束月或决策时间变化必须重新查验整个固定窗口。

### 3.2 身份与去重

以 S02 稳定 asset_id 和已核验上市身份计数，同一产品的重复输入只计一次。相同 asset_id 的完全相同资料折叠，身份或分类冲突不取第一行，排除并报告冲突；不同 ID 指向相同上市身份时也不分别计数，要求在导入页修正映射。不同代码不按相似名称自动合并。

跨市场上市、份额类别是否为同一产品不能凭名称猜测：对明确标记为重复上市的条目，选定一个代表后方可计数；未知关系保留“未核验”。相关性高的不同产品不等于身份重复，后续在 S06／S07 单独处理，不能凭相似收益直接合并。

### 3.3 漏斗与比例

顺序为：输入资料行数 → 身份合格且去重后的产品数 → 市场／类别／个股模式范围内数 → 数据合格 N。每阶段显示数量；每个产品可有多个排除原因，多个原因的数量不相加冒充漏斗减少数。

市场根据明确的上市市场／交易所映射，不能用 USD 推断美国、HKD 推断香港。未识别交易所或必要分类缺失时排除并提示补充资料。

K 必须为 20–100 的整数，拒绝布尔值和小数输入。比例用整数关系 `10*K <= 3*N`，最低 N 用 `(10*K + 2)//3`。N=0 显示比例不可计算并阻止；K 非法时报告输入错误。合法 K 且池不足时显示“候选产品池过小”，附当前 N、最低 N、缺口；不自动降低 K 或扩大市场范围。

| K | N | 数量条件 |
| --- | --- | --- |
| 20 | 66／67 | 阻止／通过 |
| 30 | 99／100 | 阻止／通过（等于 30%） |
| 50 | 166／167 | 阻止／通过 |
| 100 | 333／334 | 阻止／通过 |
| 19、101、30.5、true | 任意 | K 无效 |

搜索和表格分页只改变展示，不改变 N；市场、类别、个股开关和手动排除属于资格范围，必须重算 N。第一版没有手动加入成员功能；当前没有实际持仓，K 是目标数。

## 4. 工具分类与个股开关

默认排除个股，用户可切换允许个股。这是初始界面选项，不改写尚未确定的真实主基金投资政策。

- 排除模式：直接个股、单一公司 ADR、单只上市 REIT、直接优先股不进入；符合条件的股票 ETF、股票基金、REIT ETF 仍可进入。
- 允许模式：上述直接权益产品可在身份、结构和数据通过后进入，不要求实际选中。
- 两模式均排除第一版不支持的杠杆、反向及复杂衍生品。非投资产品的 index、FX 报价以及现金收益代理不计入可选产品 N。
- 混合、可转债、优先股基金以及商品／黄金工具需有结构核验结果。不能仅因导入类型为 ETF 就假定是普通非杠杆工具，也不能用产品名称关键词代替分类依据。

现有 S02 工具枚举不含 ADR／优先股／杠杆结构字段。S05 使用按 asset_id 绑定的独立补充资料表，保存上市市场、规范工具类型、普通／杠杆／反向／复杂结构、结构核验来源和核验状态。原始导入表不改写；缺结构证据显示“待核验”，不自动通过。已有 REIT、gold_trust 等枚举可映射，ADR／优先股必须显式补充。S05-A 先交付补充资料读取、身份绑定与来源追踪；S05-B 再用明确合成资料验证分类筛选规则。

补充资料中的“核验”指输入者提供可追溯分类依据，不冒充软件独立核实供应商。相同 ID 的补充资料重复冲突时阻止。修改工具分类需要回到导入分类修正；S05 页面提供单独的结构资料输入，不悄悄修改原始资产记录。

## 5. 分三个可验收单元交付

### S05-A：接入当前有效月度结果

复用现有 DataBundle、HKD 对照与 S03 共同窗口计算。输入适配器绑定完整资产资料、收益对照、原始时间证据和结构资料的指纹；重新验证当前结果，不接受客户端任意传入“数据合格=true”作为资格。

合格资产必须能一一对应资产资料和完整矩阵列；资料缺失、重复矩阵列、资产顺序错配、窗口不一致均报告错误，不按数组位置拼接。修改源表、时间文件、结构资料或参数后旧结果失效。输入保留原始字节散列、文件名和工作表；不修改已保存版本。

本单元独立输出 CandidateInput：身份绑定后的资产资料、HKD 月度矩阵、逐资产／逐月数据资格报告、独立结构资料、固定窗口及来源指纹。结构资料缺失保留缺失状态；此处只校验字段、身份与来源，不提前执行个股模式或结构允许规则。不接收 K，不产生 UniverseResult，不计算正式 N，也不依赖 S05-B 的筛选模块。

产物在 `outputs/acceptance/S05A/`：README、checks.txt、data_eligibility.csv、hkd_matrix.csv、input_evidence.json。分别记录合成和真实输入结果。首先验证有效数据可重现，缺月／时间证据不足可解释，输入修改使旧结果失效，源文件保持不变。已有真实数据不足时保留阻止报告，不承诺本单元形成可用的大池。

### S05-B：规则核心与合成验收

消费 S05-A 的 CandidateInput，再新增候选筛选核心和数量校验。分类、身份去重、市场／类别范围、个股模式、逐项排除原因和数量关系分别验证；先不增加工作台页面、不调用网络、不自动扩充真实产品池。

产物位于 `outputs/acceptance/S05B/`：README、checks.txt、cardinality_cases.csv、universe_audit.csv。案例至少覆盖上述边界、股票 ETF 保留、个股排除、未知结构、重复身份、空池和输入不变。真实输入不足时正常返回“候选产品池过小”，不放宽数据资格。

数值样本使用独立合成资产 ID，明确不是 100 项真实候选；禁止复制真实产品改代码来宣称候选规模达标。

### S05-C：候选筛选页面

左侧新增“候选筛选”，页面按顺序显示：输入来源与研究模式 → 市场／产品类别／个股开关 → K 与数量漏斗 → 产品表及排除原因 → CSV／JSON 导出。

产品表显示代码、名称、市场、交易币种、工具及经济类别、结构状态、有效月份、窗口和资格原因。流动性代理及费率仅在有明确来源、日期和单位时展示；当前缺失显示“未提供”。预期收益、波动、相关性、alpha／beta 等显示其后续阶段，不生成假值。

第一版不提供“生成组合”按钮，仅显示“数量条件通过／阻止”，因为成员选择和权重尚未实现。合成案例可切换 N=99／100、K=30 并立即看到边界变化。真实输入不足可继续浏览和导出诊断。

输入改变后立即撤下旧结果与旧导出，重新筛选后发布新结果；排序和分页例外，只改变表格展示。参数交互与导出不触发下载。验收覆盖宽窄屏、实际 CSV 导出、错误状态与源数据未被修改。

## 6. 模块边界与结果

规则放在 `src/portfolio/universe/`，数量校验放在 `src/portfolio/allocation/cardinality.py`；界面只调用核心。复用现有数据与日期处理，不创建第二套 HKD 计算公式。每单元实施前再细化其接口和失败测试。

数据流为现有 S02／S03 输入 → S05-A CandidateInput → S05-B UniverseResult → S05-C 页面。A 的数据资格报告不依赖 B 的产品范围筛选，B 将数据资格与范围条件合并后才计算 N。

UniverseResult 包含稳定排序的合格 asset_id、逐项资格报告、各阶段计数、K／N／最低 N／缺口、数量校验状态、固定窗口、研究模式、输入指纹和证据来源。合格矩阵列按稳定 asset_id 对齐，不加入非合格资产。历史候选池认证字段保持 false。

“数量校验通过”“声明时间逻辑通过”“本地版本时间通过”“历史候选池认证”分别记录，禁止互相替代。S05-A 只交付数据接入及其资格证据；完成后先查验，再进入 B 的筛选与数量规则。
