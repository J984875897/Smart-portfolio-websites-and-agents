# 研究工作台信息架构与界面重设计

日期：2026-10-17  
状态：用户已确认设计方向并授权连续实施；实现与验收见 UI_REDESIGN 记录。

## 目标

将当前按开发模块平铺的工作台改为按研究流程组织，使第一次使用者能知道当前状态、下一步和页面用途；同时让已有数据的使用者直接进入任何数据或证据工具。保留所有现有计算、资格判断、下载、导入和验收边界，不因界面重构改变研究结果。

默认对象是 CityU 投资课程的小组成员。首页的唯一工作是说明这次研究已完成什么、还缺什么、现在可执行的下一步；它不是展示全部技术指标的仪表盘。

## 已确认的设计决定

1. 首页采用“全面状态优先”：同时显示数据版本、候选资格、目标持仓 K、风险预览，并给一个基于当前状态的继续按钮。
2. 导航采用“流程优先”：先展示四个完成研究步骤，再将技术页面收进按研究阶段命名的高级工具组。
3. 所有页面统一重做，不只调整首页和侧栏。
4. 熟悉系统的用户仍可直接进入每项高级工具；步骤顺序提供指导，不锁定跳转。
5. 中文为界面主语言；稳定资产 ID、字段名、下载文件名和必要技术口径保留英文。

## 新信息架构

### 顶层导航

```text
研究总览

完成研究
  01 准备数据
  02 核对资格
  03 筛选候选
  04 收益与风险

数据工具与证据
  市场数据与缓存
  收益与窗口核对
  历史资格与来源
  利率与因子
```

每个工具组在侧栏中可展开／收起。侧栏仅显示组名和当前页，不在同一层级显示十个技术名词。窄屏默认收起侧栏；页面头部保留显示当前阶段和返回研究总览的入口。

### 页面映射

| 新入口 | 用户目标 | 现有功能／页面 |
| --- | --- | --- |
| 研究总览 | 查看研究状态并继续 | 新页面，读取既有会话状态，不进行计算 |
| 01 准备数据 | 导入或打开产品、价格和资料版本 | 数据导入；提供“市场数据与缓存”直达链接 |
| 02 核对资格 | 核对频率、HKD换算、共同窗口和时间证据 | 新的资格中心，串联现有日线月度、日线港币、港币收益、共同窗口页面 |
| 03 筛选候选 | 设定范围，检查 K/N 和产品资格 | 候选筛选 |
| 04 收益与风险 | 查看收益估计、相关性及指定权重风险 | 候选筛选结果内的风险预览 |
| 市场数据与缓存 | 下载、查阅与打开数据缓存 | 下载与缓存；因子与官方汇率的缓存区域 |
| 收益与窗口核对 | 直接使用收益计算和共同窗口工具 | 港币收益、共同窗口、日线月度、日线港币 |
| 历史资格与来源 | 检查历史时点资格、版本和来源记录 | 历史资格查验；数据导入的已保存版本和证据链接 |
| 利率与因子 | 查验无风险利率代理和因子文件 | 港币利率查验；因子与官方汇率 |

同一个现有计算页面可以同时在主流程和高级工具中被访问，但只能有一个实际页面实现和一份会话状态。导航入口只是指向同一渲染函数，不能复制或缓存研究结果。

## 统一页面骨架

除研究总览外，每页按以下顺序显示：

1. **页首**：阶段编号或工具组、清晰标题、一句“本页用于什么”。
2. **状态条**：该步骤的 `可继续`、`待输入`、`待核对` 或 `已阻止` 状态；状态必须来自现有计算或会话数据，不能由展示层猜测。
3. **本页操作**：仅呈现完成本页需要的输入、选择和主按钮。输入按实际依赖顺序组织，默认折叠不影响计算的技术选项。
4. **结果与下一步**：结果先给业务含义，再给具体下一步按钮或链接；无结果时说明必须补的资料。
5. **证据与下载**：表格、详细诊断、原始字段、JSON 和下载控件位于结果下方，可使用折叠区，但不得隐藏阻止原因。

每页最多一个高强调色主按钮。按钮使用明确动词，例如“查验候选资格”“计算收益与风险”“打开数据版本”，不用“提交”“继续”这类无上下文文字。

## 研究总览

研究总览不创建、修改或认证研究数据。它根据当前 `session_state` 汇总：

| 状态卡 | 已有资料时显示 | 缺失或阻止时显示 | 继续规则 |
| --- | --- | --- | --- |
| 数据版本 | 当前版本名、产品／观察数 | 尚未打开版本 | 指向准备数据 |
| 候选资格 | 合格 N、K/N、窗口 | 未查验或具体阻止原因 | 指向筛选候选，或先指向资格中心 |
| 目标持仓 | 当前 K | 默认 K=30，尚未筛选 | 指向筛选候选 |
| 风险预览 | 计算口径、波动和 DR 状态 | 未计算或候选不足 | 指向收益与风险，或先指向筛选候选 |

首页主卡根据最早未完成的主流程步骤给出一条确定的建议：

1. 未打开数据版本：准备数据。
2. 已有资料但未完成候选查验：筛选候选；若资料是日线或现有资格状态明确阻止，则推荐资格中心并显示原因。
3. 数量条件不通过：筛选候选，显示 N、最低所需 N 和缺口。
4. 数量通过但无风险预览：收益与风险。
5. 风险预览完成：显示“研究预览已完成；正式成员选择与优化尚未实施”，链接至结果和导出，不伪造下一阶段功能。

首页还提供一个次级入口“试用人工演示”，只选择现有 SYNTH 风险案例并进入候选筛选，不写入真实数据版本，也不将人工结果标为真实投资结论。

## 视觉系统

研究工作台采用“研究档案夹”而非交易终端的视觉语言：深色导航、浅色工作区、稳定的数据密度和可追溯的状态标记。

| 用途 | 颜色 | 使用规则 |
| --- | --- | --- |
| 导航和主标题 | 深蓝 `#18334C` | 侧栏、页首、主要结构 |
| 可继续／已完成 | 青绿 `#176B87` | 状态点、下一步和主按钮；不表示投资表现优异 |
| 待核对 | 琥珀 `#B7791F` | 资料不足、人工声明、待确认，不与错误混用 |
| 已阻止 | 深红 `#A63D40` | 无法进行计算的明确规则阻止 |
| 次级背景 | 雾蓝 `#EEF3F8` | 卡片、折叠区、数据区域 |
| 主文字 | 墨蓝 `#18334C` | 正文和数据标签 |

字体使用现有 PingFang SC／系统字体。标题层级减少为页面标题、区块标题、标签三档；表格使用等宽数字或原有系统数字呈现。卡片用于状态和下一步，不把每个输入项包成卡片。图表保留当前正负风险贡献配色和明确轴标签；相关性固定 -1 至 1 色域。

## 状态和错误规则

1. 同一研究输入变化后，已有规则清除候选和风险结果；新壳层必须反映其清除状态，不保留“已完成”视觉标记。
2. 真实日线仍为 N=0 时，概览和资格中心必须明确显示“需要月度准备”，不能使用人工演示状态填充真实状态卡。
3. `partial`、`tls_error`、人工时间声明和历史候选池未认证属于待核对或阻止状态，页面必须显示下一步资料要求，不能使用成功绿色。
4. 研究总览和入口卡不直接调用下载、网络、风险计算或数据保存；所有写入动作保留在原功能页的明确按钮中。
5. 从高级工具跳转回主流程时，保持当前研究状态；换数据版本后，依赖旧版本的上传证据、候选结果、权重和风险下载仍按既有规则清除。

## 技术架构

新增一个集中定义，负责导航结构、阶段标签、状态文本和目标路由。`app/main.py` 只选择页面与渲染函数；不再在主文件内维护十项平铺字符串和 `if` 链。

建议新增：

- `app/views/workspace_shell.py`：全局样式、侧栏分组、状态条、统一页首和研究总览。
- `app/views/workspace_state.py`：从既有 `session_state` 读取只读研究状态，输出稳定的数据类或字典；不能修改当前 bundle、筛选结果或风险预览。
- `app/views/eligibility_hub.py`：资格中心，说明哪些检查可用、状态和下一步，并链接／调用已有资格工具；第一版不把四种底层计算合并为一个新计算器。
- `app/views/page_chrome.py`：页面骨架辅助函数，确保每页的页首、状态、说明、结果和证据结构一致。

现有业务页面保留其已有核心计算函数和会话键。逐页迁移时只替换标题、说明、输入分区、结果顺序和路由入口；任何计算逻辑改动必须另立任务并有相应数值测试。

## 迁移顺序

1. **壳层与研究总览**：新导航、阶段路由、状态读取和首页；不改变现有页面内容。
2. **主研究流程**：准备数据、资格中心、候选筛选、收益与风险，完成第一次用户可走通的流程。
3. **高级工具**：下载与缓存、收益与窗口核对、历史资格与来源、利率与因子，统一页面骨架和跳转。
4. **文案与帮助**：更新使用指南，提供首次研究、人工演示、已有数据快速进入和常见阻止状态的说明。
5. **验收**：全量回归、状态失效测试、所有路由、宽／窄屏截图、实际导出、没有横向页面溢出或重叠。

每一阶段可独立验收，避免把导航问题、业务计算问题和视觉问题混合排查。

## 验收标准

- 新用户从研究总览可在不阅读技术术语的前提下找到“准备数据”与当前下一步。
- 有经验用户可在两次点击内从侧栏进入任一现有工具。
- 所有原有功能仍有且只保留一份计算状态；同一页面从不同入口进入结果一致。
- 每个阻止状态给出原因和可执行的下一步；没有使用绿色掩盖资料不足。
- K、N、风险预览和真实 N=0 的含义与既有验收逻辑一致。
- 1440、720、390 像素宽度下导航、状态卡、表格和图表可使用，无正文重叠或页面级横向溢出；容器级表格／热图横向滚动允许且有说明。
- 所有当前测试保持通过；为状态读取、路由、跳转和旧结果失效新增页面测试。浏览器验收检查主要路径与实际下载。

## 明确不在本次范围

- 不实现 S07 成员选择、S08 utility／优化、做空、CAPM／FF3／FF5 或新风险模型。
- 不把人工 SYNTH 案例升级为真实市场资料。
- 不下载、修改或认证外部来源；不解除真实日线 N=0 或历史候选池认证限制。
- 不合并现有计算模块或改变数据合同，只为视觉一致性做结构化展示和路由重组。
