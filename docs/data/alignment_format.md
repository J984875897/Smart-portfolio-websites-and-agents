# 月度共同窗口与时间证据

本页说明 S03-B 输入约定。先在「港币收益查验」生成有效 HKD 对照，再到「共同窗口查验」补充时间证据。窗口查验不改变原始导入版本。

## 两种日期不要混淆

收益表里的 `2025-01-31` 表示 **2025 年 1 月这一月度期间**。时间证据中的 `2025-01-31T16:00:00+08:00` 才表示实际估值发生在香港时间几点。

美国同一月的估值可能在香港的次日才可得，因此两个市场同属 1 月，不等于香港 1 月 31 日下午已经可以用到美国的完整 1 月收益。系统把带时区时间转换成统一时间后比较，不从日期标签猜测发布时间。

## 时间证据 CSV／XLSX

每个资产、每个月一行。`asset_id` 必须与 HKD 对照表一致，可下载界面模板填写。Excel 可选择工作表。时间必须带 `Z` 或 `+08:00`、`-05:00` 等偏移；没有时区会被阻止。纽约夏令时和冬令时应填写该观察实际适用的偏移。

| 字段 | 含义 |
| --- | --- |
| asset_id | 收益对照中的稳定资产标识 |
| date | 收益期间的自然月末标签，严格 YYYY-MM-DD |
| market_timezone | 估值市场时区，Asia/Hong_Kong 或 America/New_York |
| price_start_at | 上一月末估值的实际时间 |
| price_end_at | 本月末估值的实际时间 |
| fx_start_at | 起点汇率的实际观察时间，HKD 本币可留空 |
| fx_end_at | 终点汇率的实际观察时间，HKD 本币可留空 |
| available_at | 这一行全部输入及版本最晚可得的时间 |
| source_name | 时间资料来源及月末估值依据；不可为空 |

`available_at` 应考虑两端价格、分配及拆股调整、月度总收益、两端汇率和所使用的历史修订版本。它必须不早于任何输入观察时间。单有收市时间不等于供应商已经发布数据。

对于直接导入月度总收益，起止估值时间仍应对应提供者该期间的真实估值端点。对于已确认调整价格，填入实际用于计算该月收益的两端价格时间。软件不能从总收益数值反推这些资料。

价格时间按市场所在日历月核对；FX 按 UTC 日历月核对。实际观察须位于对应起止月份，距离该月末不超过 7 天。**7 天是研究中的陈旧性阈值，并非交易所日历认证。**来源仍需核实采用该市场当月最后有效估值；特殊停牌、长假或其他例外不会自动放行。不同市场与汇率的估值可能非同步，应在报告中披露。

原始 CSV／XLSX 文件、工作表、物理行和 SHA-256 会附在输出。上传表中自行填写的同名来源字段不能取代实际文件证据。

文件读取后，程序接口要求将完整原表交给查验器；如在内存中筛行、重排或改值，须重新保存并导入新文件。否则原文件与当前表可能不一致，查验器会拒绝继续。界面的直接上传路径自动遵守这项规则。

## 60 个月是什么意思

结束月份选择 `2025-01` 时，固定窗口是 **2020-02 至 2025-01**，恰好 60 个月。每个产品必须在这 60 个相同月份都有有效、且在指定决策时点已经可得的 HKD 收益。

- 只有 59 个月：排除，列出缺失月份。
- 中间缺 1 个月、但更早还有多年数据：仍排除，不用更老的数据替补。
- 缺少换算汇率或时间证据：对应月份无效。
- 真正 0% 收益：有效；缺失值不会替换成 0%。
- 决策时点正好等于最晚可得时间：允许。

同时，决策日期必须已到达该市场的自然月末；外币换算还要求 UTC 日期已到月末。没有交易日历认证时采取此保守规则：即使最后报价是 1 月 24 日，也不能在 1 月 24 日就使用完整 1 月收益。这里的月末日期门槛还须与实际观察、发布时间一起通过，不表示月末当天零点自动拥有所有数据。

报告里的通过数只是共同窗口检查结果。正式候选数 N 还需要 S05 的范围、分类、去重等检查，不能用这里的数量直接判断 K/N。

## 使用范围

这一步处理已明确月度期间的收益及其时间证据。日线自动月度聚合、交易所日历认证和自动获取历史发布时间尚未接入；不能直接把 S01 日线标成已对齐。

时间证据由使用者提供，软件验证其结构和逻辑，不独立认证其真实性。当前下载的复权历史数据若包含后来修订，不能仅填写一个早期时间就宣称已重建当时可用版本。没有此证据时，研究只能按其真实可得时间或明确的回溯限制解释。
